# Piesson Profile Dashboard

Updated: 2026-09-21

## Overview

Piesson's public GitHub profile is generated from three SVG panels:

1. yearly GitHub activity;
2. weekly pull requests, social posts, and hand-filed metrics;
3. twelve-week cumulative pull requests/social posts and supporting totals.

The Vault monorepo is authoritative for code. `Piesson/Piesson` is the public
runtime repository and remains authoritative for files generated by its GitHub
Actions.

## Data ownership

| Data | Source | Update path |
|---|---|---|
| Pull requests | `get_weekly_pull_requests.py` with exact KST boundaries | automatic |
| Social posts | `/today` review block | local nightly sync |
| Talks with users | `/today` review block | local nightly sync |
| Coffee chats | `/today` review block | local nightly sync |
| Workouts | `/today` review block | local nightly sync |
| Blog posts | `/today` review block | local nightly sync |
| Claude/Codex tokens | local usage tools | stored privately in `data.json`, never rendered |

## Daily-note format

`/today` records the previous KST calendar day in the note created today:

```markdown
# 어제의 점검
<!-- piesson-review-date: 2026-09-20 -->
- 소셜 포스트: 2
- 유저 대화: 1
- 커피챗: 0
- 운동: 1
- 글: 0
```

The date comment and five labels are a machine-readable contract. Values may be
edited later. Blank values mean zero.

`dashboard/sync_daily_metrics.py` scans `200-Daily/*.md`, validates blocks, groups
them by ISO week, and replaces the five weekly totals. It never increments the
existing value, so reruns are idempotent and edits are retroactive. Recomputed
entries carry `manualMetricsSource: daily-notes`, distinguishing an honest all-zero
week from an untouched legacy gap.

Migration behavior:

- reviews before 2026-09-21 are ignored, preserving W38 and older Slack-filed history;
- a managed week with at least one block is recomputed from its available days;
- missing days contribute zero;
- conflicting duplicate dates or malformed blocks stop the sync;
- notes older than the current/history retention window are ignored.

## Local 00:05 KST automation

LaunchAgent: `scripts/com.piesson.weekly-tokens.plist`

Wrapper: `scripts/update-weekly-tokens.sh`

```text
latest Vault main
  → isolated cron worktree
  → pull upstream-generated Piesson data
  → recompute 200-Daily metrics
  → refresh private token totals
  → commit only dashboard/data.json
  → subtree delivery to Piesson/Piesson
  → upstream dashboard regeneration
```

The wrapper shares the automation mutex and never resets a dirty or interrupted
worktree. Daily metrics can still be delivered when token providers fail; the
wrapper reports the token failure with a non-zero exit afterward.

## Weekly reset

`.github/workflows/update_dashboard.yml` runs Monday at 07:00 KST. It:

1. confirms the closing week's machine-counted activity when the API is available;
2. writes the closing week into `weeklyHistory`;
3. keeps the newest twelve completed weeks;
4. resets the current week;
5. regenerates history, current-week, and running-total SVGs;
6. updates content-hash image URLs and README timestamps.

A push to `dashboard/data.json` regenerates the public assets without performing a
weekly reset. During generation, the pull-request counter searches merged PRs by
the profile owner in the current week's exact KST→UTC window. API failure keeps
the previous count; it never writes a false zero.

## Grouped metric compatibility

Daily-note-managed weeks use:

```json
"socialContent": {"total": 3},
"workouts": {"total": 1}
```

Historical weeks may use platform/activity detail keys. Readers use
`dashboard/metric_totals.py::grouped_total`; an explicit `total` always wins to
prevent double counting.

## Slack retirement

The Slack slash-command, reminders, confirmation messages, weekly summaries,
Cloudflare Worker bridge, response workflow, and webhook secret were retired.
Slack is not a fallback input path. Reintroducing it would create a second writer
and break deterministic note-based recalculation.

## Validation

From `apps/piesson/`:

```bash
pytest -q
bash scripts/test-update-weekly-tokens.sh
python3 dashboard/generate_svg.py
python3 dashboard/generate_progress_chart.py
```

Before considering a dashboard change complete:

1. run the tests;
2. deliver through a Vault PR and automatic mirror;
3. wait for upstream generators;
4. verify the public README points to current content-hash SVG URLs;
5. capture screenshots from the actual public GitHub profile.
